# /fix-issue <issue>

$ARGUMENTS 에 해당하는 이슈를 표준 절차로 고친다.

절차:
1. 이슈 내용을 파악한다(이슈 트래커가 있으면 조회, 없으면 사용자 설명 기준).
2. 관련 코드를 찾아 **근본 원인**을 규명한다. 증상만 덮지 않는다.
3. 최소 변경으로 수정한다. 주변 스타일을 따른다.
4. 수정을 실제로 검증한다(빌드/실행/테스트로 재현 → 해결 확인).
5. 무엇을 왜 고쳤는지 요약한다. 커밋/푸시는 사용자 요청 시에만.

주의: 스코프를 벗어난 리팩토링을 끼워 넣지 않는다. 별도 개선거리는 따로 제안한다.
