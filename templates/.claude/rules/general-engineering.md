# 공통 엔지니어링 규칙 (스택 무관)

모든 AIRISS 레포에 적용되는 기본 규칙.
※ 표준 원본: claude-code-standard v0.8 — 이 파일은 레포에서 직접 수정하지 말 것(표준 레포 PR로).

## 핵심 행동 원칙
AI는 코드를 못 짜는 게 아니라 **너무 많이·너무 빨리 짜는 게** 문제다. 아래는 그 브레이크다.

1. **코딩 전에 생각한다 (Think Before Coding)** — 추측하지 않는다. 모르면 모른다고 하고, 방법이 여러 개면 **선택지와 트레이드오프를 먼저 드러낸 뒤** 진행한다. 혼란을 감추고 일단 짜지 않는다.
2. **단순함 우선 (Simplicity First)** — 문제를 푸는 **최소한의 코드**만. 미래를 위한 추측성 추상화·일반화를 넣지 않는다.
3. **외과적 수정 (Surgical Changes)** — **요청 범위만** 건드린다. 옆 코드를 겸사겸사 고치지 않는다. 별도 개선거리는 따로 제안한다.
4. **목표 기반 실행 (Goal-Driven)** — 성공 기준을 정의하고, **검증될 때까지** 반복한다.

## 작업 순서
- 큰 작업(새 기능·구조 변경)은 **조사 → 플랜 → 승인 → 구현 → 검증** 순서로 간다. 조사 없이 코딩을 시작하지 않는다. → `/plan-feature`
- 작업 중 플랜과 달라지는 지점이 생기면 **말없이 바꾸지 말고** 알린다.
- 한 세션에 무관한 작업을 섞지 않는다. 목적이 바뀌면 새 세션으로.

## 응답 · 소통
- 사용자에게는 **한국어**로 답한다(기술 용어는 영어 그대로 허용).
- 확실하면 행동한다. 이미 정해진 것을 다시 묻지 않는다.
- 파일 참조는 클릭 가능한 경로 형식으로(`경로:라인`).

## 코드 작성
- **재사용 우선**: 새로 만들기 전에 기존 함수·유틸·패턴을 먼저 찾는다.
- **주변 코드를 닮게**: 네이밍·주석 밀도·관용구를 파일의 기존 스타일에 맞춘다.
- 요청받지 않은 대규모 리팩토링을 끼워 넣지 않는다.
- 추측성 주석/과도한 방어 코드로 부풀리지 않는다.

## 코드 품질 (지킬 것만 짧게)
- **이름이 설명이 되게.** 주석으로 설명해야 한다면 이름이 틀린 것이다. 축약어·`data`·`temp` 같은 무의미한 이름을 쓰지 않는다.
- **함수는 한 가지 일만.** 중첩이 깊어지면 이른 반환(early return)으로 편다.
- **중복은 세 번째에 추출한다.** 두 번은 우연, 세 번이면 패턴. 한 번 보고 미리 추상화하지 않는다.
- **죽은 코드는 지운다.** 주석 처리해서 남기지 않는다 — git 이력에 있다.
- **에러를 삼키지 않는다.** 빈 catch 금지. 처리하지 못할 예외는 올려보낸다.
- **매직 넘버·하드코딩 문자열 금지.** 상수·설정·리소스를 참조한다.
- 리팩토링은 **동작을 바꾸지 않는다.** 버그를 발견하면 따로 알리고 따로 고친다. → `/refactor`

## 프로젝트 구조
- 새 파일은 **이 레포의 기존 구조가 정한 자리**에 둔다. 새 최상위 폴더를 임의로 만들지 않는다.
- 어디에 둘지 애매하면 **가장 비슷한 기존 기능이 어디 있는지 먼저 찾는다.** → `/scaffold-feature`
- 의존 방향을 거스르지 않는다(UI → 도메인 → 인프라 등 이 레포의 계층 규칙).
- 구조를 바꿔야 한다면 코드보다 먼저 말한다.

## 커밋 (요청 시에만)
- 사용자가 명시적으로 요청할 때만 커밋/푸시한다. → `/commit`, `/open-pr`
- **기본 브랜치에 직접 커밋하지 않는다** — 필요하면 브랜치를 먼저 만든다.
- 커밋 메시지는 이 레포 관례를 따르고, 없으면 Conventional Commits(`feat:` `fix:` `refactor:` `docs:` `test:` `chore:`). **무엇을 했는지가 아니라 무엇이 달라지는지**를 쓴다.
- 한 커밋에 서로 다른 목적을 섞지 않는다.
- 훅이 실패하면 우회(`--no-verify`)하지 말고 원인을 고친다.

## 검증
- 변경 후 "된다"고 말하기 전에 실제로 빌드/실행/테스트로 확인한다.
- 테스트가 실패하면 실패했다고 출력과 함께 정직하게 보고한다.
- 건너뛴 단계가 있으면 건너뛰었다고 말한다.
- VS Code에서 작업 중이면 편집 직후 **IDE 진단(Problems 패널)** 을 확인한다(`mcp__ide__getDiagnostics`). 컴파일러를 돌리기 전에 타입 오류·누락 import를 먼저 잡을 수 있다.

## 보안
- 비밀(키·토큰·비밀번호)을 코드/설정/문서에 하드코딩하지 않는다.
- 커밋 전 변경분에 시크릿이 섞였는지 확인한다.
- 되돌리기 어렵거나 외부로 나가는 작업은 먼저 확인받는다.
