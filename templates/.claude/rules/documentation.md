# 문서 작성 규칙

Markdown·문서를 다룰 때만 로드된다(항상 로드되지 않음).
※ 표준 원본: claude-code-standard v0.8 — 이 파일은 레포에서 직접 수정하지 말 것(표준 레포 PR로).

## 원칙
- **코드에서 확인된 사실만 쓴다.** 추측으로 문서를 채우지 않는다. 확인 못 한 건 "확인 필요"로 남긴다.
- **독자를 먼저 정한다.** 신규 팀원용인지, 유지보수자용인지, 외부용인지에 따라 쓸 내용이 달라진다.
- **문서는 코드보다 빨리 낡는다.** 낡을 내용(파일 목록, 함수 시그니처)은 최소화하고, 안 낡는 것(왜 이렇게 했는가, 함정, 규약)을 쓴다.

## 형식
- 제목은 문서의 **이름**이지 요약이 아니다. 한 줄 요약은 제목 아래에.
- 문단보다 **표·목록**. 스캔 가능하게 쓴다.
- 코드 블록에는 **언어를 명시**한다(```powershell, ```csharp).
- 명령 예시는 **실제로 돌아가는 것**만 적는다. Windows 팀이면 PowerShell 기준으로 쓰거나 병기한다.
- 링크는 상대 경로로(`[ADOPTION.md](ADOPTION.md)`). 절대 URL은 외부 자료에만.

## 하지 말 것
- ❌ "간단히", "쉽게", "그냥" 같은 난이도 단정 — 읽는 사람에겐 안 쉬울 수 있다.
- ❌ 같은 내용을 여러 문서에 복사 — **단일 출처**를 정하고 나머지는 링크한다. 복사본은 반드시 낡는다.
- ❌ 스크린샷으로만 설명 — 텍스트로도 따라갈 수 있게.
- ❌ TODO만 잔뜩 남기고 끝내기.

## 이 레포의 문서 구조
- `docs/10_Raw_Sources/` — 기획·리서치 **원천. 읽기만 하고 수정하지 않는다.**
- `docs/20_The_Wiki/` — 코드를 분석해 정리한 지식. 문서 간 `[[문서명]]` 위키링크로 연결. → `/doc-sync`
- `CLAUDE.md` — 프로젝트 오버뷰. **짧게 유지**(200줄 이내). 상세는 `.claude/rules/`로.
